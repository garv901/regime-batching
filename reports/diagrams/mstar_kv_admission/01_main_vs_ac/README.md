# KV admission: main vs AC (admission control)

Reading order: 01, 02, 03. Orange (accent) marks the focal element of each diagram, not a fixed side: in 01 it is the fail-hold-retry loop, in 02 the fit test, in 03 the AC curve. All numbers are measured on burst_v2 (46 equal long requests at t = 30 s plus short requests at 9/s), except the curve shapes in 03, which are illustrative.

1. `01_main_oom_loop/main_oom_loop.html` - Flowchart. On main, `admit()` reserves only what the current step writes, so the pool over-commits. When a step needs a page and the pool is full, eviction cannot help, no offload victim exists (`cpu_offload_pages = 0`), and the worker holds the blamed request for 50 ms and retries. A held request keeps its pages, so only completion frees pages. Measured: short-request E2E 422 s, 1,744 timed-out requests, 44 output tok/s.
2. `02_ac_gate/ac_gate.html` - Flowchart. AC puts each request in a strict FIFO wait list that holds no pages. Only the head computes its reservation (prompt minus cached pages, plus `max_tokens`, summed over labels); a request that cannot fit even an empty pool fails at once, and otherwise it runs only if `outstanding + need <= free + evictable`. An admitted request never hits allocation failure. The cost is that every request is charged its full `max_tokens` up front.
3. `03_pool_pages_over_time/pool_pages_over_time.html` - Line chart, illustrative shape (not measured curves). main admits all 46 long requests and pins the pool at its ceiling; AC admits only what fits at full reservation and rises in a staircase below the ceiling. Measured outcomes: main short E2E 422 s and 44 tok/s, AC 15.9 s, 0 timeouts and 648 tok/s.

Each folder holds the source `.html` (open it in a browser), an exported `.svg` (diagram only, without the page header) and a 2x `.png` preview. The PNG was rasterized with `rsvg-convert` on a machine without the Geist and Instrument Serif fonts, so it uses fallback fonts. Use the `.html` or `.svg` for final figures.
